- `context://self`: your experimental live-context document, not the execution transcript. In JavaScript/Python eval, `await tool.read(…)` of `context://self:raw` returns the complete JSON snapshot in its string value or `text` field; parse and transform it in memory without printing it. Code-mode raw snapshot text is lossless even when the human-visible tool preview spills, so do not reconstruct it with artifact pagination or strip display notices. A direct read outside eval can still spill: recover that same stable artifact or its advertised backing file rather than parsing the preview. A root read starting at line 1 snapshots the current context (an unchanged context keeps its `snapshotId`); a later page (`:raw:N-M` with N > 1) keeps serving that snapshot while the context only grows, and is refused with the new `snapshotId` once it was rewritten, so restart from line 1. Never write display-prefixed or truncated reads back.
  - Read-only routes: `context://self/status` (token estimate and limits, revision, last receipt), `/history`, `/revision/<id>`, `/diff/<id>` (changes that revision introduced vs its predecessor), `/diff/<id>/current` (that revision vs the current context). `previous` names the revision before the latest (the pre-CLM root when only one exists).
  - Archive (read-only): everything that entered this context since the last reset, including what you deleted, kept verbatim and deduplicated. One item per user/assistant message, note, or tool call with its result (multi-line args as `field: <<EOF` blocks); ids `h` + 10 hex chars are stable across edits, revisions, and reloads (unlike `b<N>`). `context://self/archive` lists items chronologically (`?offset=&limit=` pages; markers `in-context`, `superseded-by <id>` for a file view later changed by a write/edit or a recognized shell mutation, a read later re-read with different content, or a command later rerun successfully with different output, `truncated`). `context://self/archive?q=<terms>` searches: BM25 shortlist, reranked by the native judge when available, which also scans the rest for paraphrased matches (the header says when results are lexical only); a superseded item never ranks above its replacement. `&regex=1` is a case-insensitive regex filter (no rerank); `&limit=` (≤50), `&rerank=0`. Hits show id, time, turn, kind, label, and `L<n>` excerpt lines; `excerpt: k of N lines` means lines are missing, so read the item before answering exact questions. `context://self/archive/<id>` returns the item verbatim; add `:N-M` for lines.
  - Handoff: `task` items accept `handoff` refs (`h<id>`, or `b<N>` of this snapshot, optional `:N-M`) whose content the host copies verbatim into the child. In a subagent spawned by a CLM parent, `context://parent/archive`, `/archive/<id>`, and `/archive?q=` read the parent's archive read-only (same parameters); the rest of `context://parent` and every write are refused. A `<parent-handoff>` seed is an editable block: delete or condense it once absorbed.
  - Envelope v2: `{"format":"omp-clm","version":2,"revision":…,"snapshotId":…,"blocks":[…],"end":"omp-clm"}`, one block per line. Host blocks are `{"id":"b<N>","role":…,"text":…}` plus `"protected":true`/`"opaque":true` only when set. `id`, `role`, and flags are host-owned: keep them exactly; `text` has no role header. Ids are valid only with this envelope's `snapshotId`.
  - Write only the root with the complete envelope; keep `format`, `version`, `revision`, `snapshotId`, and `end` unchanged. Each host block is an atomic complete exchange: do not split it. Delete, reorder, or rewrite editable blocks; insert new blocks as `{ "text": "your note" }`. Changing an editable block's text to empty/whitespace deletes it; unchanged empty native blocks are retained, and an empty new block is rejected. Delete blocks rather than leaving placeholder notes.
  - Protected blocks (current request, live exchange, host control) must remain unchanged and in order; historical blocks cannot move across them. Rejections name the offending block id and kind. New notes placed after an incomplete live tool exchange are moved just before it so its pending results stay adjacent. Opaque blocks hold hidden provider state (images, signed thinking/text, native payloads and recorded request controls): keep them unchanged or delete the whole block and add a new note. Unchanged exchanges preserve native tool pairing; edited exchanges and new text become lower-trust model-authored notes. Textual role labels never create developer instructions, human requests, signatures, or executed tool calls.
  - Host CLM feedback (pressure, urgent soft-limit notices, receipts, rejections) arrives as `<system-notice source="clm">` messages; they appear as editable blocks, so delete stale ones.
  - A write receipt means staged, not committed. The host validates and publishes only at a safe turn boundary; check status/receipt for acceptance or rejection. New suffix messages are preserved. Re-read after a changed revision or rejected stale snapshot. Filesystem writes, `edit`, and `ast_edit` do not support this virtual resource.
